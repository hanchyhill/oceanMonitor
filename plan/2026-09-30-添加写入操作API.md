我需要在 @bulletin\bule-koa.js 中添加写入操作的 API。
现在有一个新的功能需求，读取 tc-ens 接口获取台风集合预报数据，得到台风集合预报数据后，通过算法，关联各个不同机构之间的台风，形成统一的新的台风编号，然后将这些数据写入数据库，以便后续查询和使用。因为现在各个不同机构，其编号是互相独立的，不知道 A 机构的台风编号对应 B 机构的哪个台风编号，所以需要通过算法进行关联。同样的，即使是同一家机构，不同起报时刻的台风编号也是独立的，也需要通过算法进行关联。
为了实现这个功能，先新增一个只负责写入统一编号的 API。另一个项目读取现有 tc-ens 接口并负责关联算法；算法规则后续单独制定，本项目暂不计算关联结果。
我在 @bulletin\database\privateConfig\private.dbConfig.js 当中，新增了写入权限的配置 configWriteTC。
需要预留的新增字段包括如下：

- unidIns // 跨起报时刻的同一家机构的统一台风编号，文本类
- unidGlobal // 跨起报时刻的各家机构的统一台风编号，文本类
- tsid // 关联主观预报机构的台风编号，文本类

## 实施方案

### 1. 明确职责与接口契约

- 保留原有时间范围查询，并为 `GET /api/?interface=tc-ens` 增加按单个起报时刻查询：`/api/?interface=tc-ens&initTime=2026-09-30T00:00:00Z&basin=WPAC`。指定 `initTime` 时不要求 `gt`、`lt`，默认查询该时刻所有机构的完整预报数据；`ins` 可选，用于缩小机构范围。按 UTC 的同一分钟窗口筛选 `initTime`，与现有 `tc-ens-detail` 的时次精度保持一致；提供了无效时次则返回 `400`，无数据返回空数组。原有按范围查询的行为保持不变。
- 外部项目以该时次的 GET 结果完成关联，再调用新增的 `POST /api/tc-ens/identifiers` 写入结果。本项目只校验请求、定位 Cyclone 文档和保存编号，不读取路径参与匹配，也不生成编号。跨时次关联时，由外部项目分别读取相关时次。
- 写入请求体示例：`{"initTime":"2026-09-30T00:00:00Z","updates":[{"id":"<Cyclone._id>","identifiers":{"unidCurrent":"CUR-001","unidIns":"INS-001","unidGlobal":"GLB-001","tsid":"1234"}}]}`。`id` 使用 GET 响应中的 `_id`；`initTime` 指明本批次的起报时刻，每条 `_id` 必须属于该时次。`identifiers` 至少包含一个字段，只写传入的字段。暂不通过 `null` 或空串清除旧编号；确需清除时另定显式操作。分批调用，例如每批最多 100 条，并限制请求体大小。
- 逐条返回 `id`、`updated` / `unchanged` / `notFound` / `timeMismatch` / `conflict` / `error` 状态与汇总数量，让调用方能安全重试失败项；不回传完整路径。重复提交同一值应得到 `unchanged`，不得产生额外字段变更。

### 2. Token 鉴权

- 用 Node `crypto.randomBytes(32).toString('hex')` 预生成一次高熵 token，部署时放入服务端环境变量 `TC_ENS_WRITE_TOKEN`（或未纳入版本控制的私有配置）；仓库和计划文档均不保存 token 明文。外部项目通过 HTTPS 请求头 `Authorization: Bearer <token>` 发送。
- 写入路由先验证 token 再处理业务数据；未配置 token 时仅写入路由返回 `503`，不影响原有读取接口；缺失或错误 token 返回 `401`。比较时使用固定时间比较方式，并避免在请求日志、错误信息中输出 token。当前服务端允许跨域读取；写入 token 只配置给外部服务，不能放进 Vue 前端。
- 限制请求体大小与单批条数，记录调用时间、处理条数、失败状态等审计信息，不记录凭据和完整轨迹。

### 3. 模型与数据库连接

- 在 `bulletin/database/initMultiDB.js` 的 Cyclone schema 增加 `unidCurrent`、`unidIns`、`unidGlobal`、`tsid` 四个可选 `String` 字段；同步核对 `bulletin/database/tc-ens-schema/db.schema.js` 和外部 `ruc-tc` 的 schema，防止其他程序重存文档时丢字段。现有 `tcID` 保持原义。
- 复用同一份 Cyclone schema，通过 `configWriteTC` 新建独立的写入连接和模型 `connectWriteTC()`，保留 `connectTC()` 的只读连接。写入连接在首次有效写入请求时按需建立；连接失败返回 `503`，后续请求可重试。仍需在真实数据库环境检查断线重连及读写连接是否指向同一集合。
- 用 `_id` 精确定位回写记录，并核对记录的 `initTime` 与请求时次一致；确认读写连接指向同一数据库及 `cyclones` 集合。写入按 `_id` 定位，现阶段不需要为新编号增加索引；后续有按编号查询的需求再评估。

### 4. 严格限定更新范围

- 对 `initTime` 和 `updates` 做白名单校验：时次必须是带时区的有效时间；`id` 必须是合法 ObjectId；`identifiers` 只能包含四个编号字段，值必须是非空且长度受限的字符串；拒绝重复 `_id`、额外字段与超限批次。不得将请求对象直接传给 MongoDB 更新方法。
- 用明确构造的 `$set` 更新文档：只包含本次请求的编号字段。不得使用 `replaceOne`、整文档 `save()` 或复制原始请求体；不得 `$unset` 路径信息，也不得改动 `tracks`、`detTrack`、`loc`、`detLoc`、`tcID`、`initTime` 等字段。若要求物理上仅改变编号字段，更新操作还须禁用自动 `updatedAt` 写入。
- 先读取目标文档的 `initTime` 和编号字段；时次不匹配则跳过并报告，如果已有编号值与新值不同，默认返回 `conflict`，防止误覆盖。确需纠错时，另定义带期望旧值的条件更新操作。写入条件同时包含 `_id`、起报时刻窗口和旧编号值，避免读取和更新之间被其他请求改号；若条件不再匹配，按冲突处理。
- 使用写入连接对每条 `_id` 执行原子条件更新，并逐条统计结果；部分成功时明确返回已成功及失败项，调用方只重试失败项。不要因为某条失败而重写整批 Cyclone 文档。
